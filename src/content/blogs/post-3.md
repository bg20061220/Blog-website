As a first-year student, applying to jobs was completely new territory and exhausting. The biggest pain point was tailoring my resume for every single application. After wrestling with this for about a month, I decided to build something for myself to solve this problem.

## Version 1: Solving My Own Problem

I started simple, focusing on solving this problem for myself using free resources. After some research, I landed on a solid architecture:

- **Storage:** Microsoft Azure Blob Storage for my projects and work experiences
- **Vector Database:** Azure Cognitive Search with 384-dimensional embeddings
- **Embeddings:** Sentence Transformers (all-MiniLM-L6-v2) to convert text into vectors
- **Retrieval:** HNSW algorithm to find the most relevant experience chunks
- **Generation:** Ollama's Llama 3.2 (7B) to generate tailored bullet points

The RAG pipeline worked beautifully but only on my local machine. I wanted anyone to use it, so I decided to build version 2.

## Version 2: Building for Everyone

The biggest challenge was making it scalable and cost-effective. Azure was too complex and expensive for a multi-user application, so I made some key architectural changes:

**The New Stack:**
- **Database:** PostgreSQL + pgvector extension (combining relational database with vector search capabilities)
- **Data Management:** Local JSON files exported to PostgreSQL
- **Backend:** FastAPI with endpoints for bullet point generation and top-3 experience extraction
- **Frontend:** React app for a smooth user experience
- **Embeddings & LLM:** Same setup as v1 (MiniLM + Llama 3.2)

## The Privacy Problem

Here's where things got interesting. Since the tool handles personal resume data, I couldn't just host it on a server. The solution? **Docker.**

I dockerized the entire application and made it open source on GitHub. Now anyone can run it locally and their data never leaves their machine, and there are zero privacy risks.

## What I Learned

This project took me through the full product lifecycle:
1. **Experiencing the problem** firsthand as a job applicant
2. **Building v1** to solve my own pain point
3. **Redesigning the architecture** to make it scalable
4. **Tackling distribution** with Docker for privacy-first deployment

Going from "this works on my laptop" to "anyone can use this" taught me more about software development than any tutorial ever could.
